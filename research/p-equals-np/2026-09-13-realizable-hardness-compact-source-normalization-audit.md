## Exact source representation and semantic renaming

Use the existing DataEncode instances, with a new explicit source alias:

    BinaryTriple := Nat * (Nat * Nat)
    Source := List BinaryTriple * List Bool
    wire(S) := DataEncode.bitstringEncode S

Require equal row/RHS lengths for the mathematical source domain. These are lists of equation occurrences, not sets; order and duplicates are retained. A Bool RHS is interpreted in ZMod 2. DataEncode Nat is exactly DataEncode (Nat.bits n), as verified in Encoding/DataEncode.lean:94. This is compact binary labeling; there is no unary conversion of the original numeric names and no ambient N in this source wire. An existing Instance N m can map to this representation through `.val`; conversely the semantic source can use assignments Nat -> ZMod 2 without enumerating an ambient label universe. This newly selected composite format uses existing concrete encoding machinery; it is not already the accepted upstream source-reduction output format. That upstream equality remains an obligation.

Flatten triples in their actual row/position order into L, length 3m. For a used label v define first(v) = L.idxOf v. Set the renamed label at occurrence q to first(L[q]). It is less than 3m because q itself is a witness. The new variable carrier is Fin (3m), with no assertion that every name is used: first-occurrence positions leave holes. This avoids an unnecessary dense-rank/dedup algorithm. For used v,w, first(v)=first(w) iff v=w, by recovering L at the shared index. Thus equalities and repetitions among source labels are preserved exactly.

For a source assignment a, define output assignment b(k)=a(L[k]) for every k:Fin(3m). Then b(first(v))=a(v). For an arbitrary output assignment b, define decoded a(v)=b(first(v)) when v occurs, and zero otherwise. Both directions give the same value at every row position and preserve every row's GF(2) parity/RHS and its violation indicator. Consequently the ordered list of violated rows and violation count are identical. Source labels that never occur require no output variable; their arbitrary assignments have no effect. Unused new indices can have arbitrary values. Empty m gives the empty Fin carrier and vacuous row correspondence without choosing an inhabitant.

Immediate semantic targets: flatten_length; first_lt_of_mem; get_first; first_eq_iff_on_used; normalized_row_values in both assignment directions; exact_sourceViolations_transport; normalized_vars_lt_3m. These must be definitions and proofs, not fields supplied by a caller.

## Size and runtime boundary

All normalized labels are <3m. UnaryList.length_encTriple gives 4(a+b+c)+10 for one unary triple, hence a conservative normalized table bound 2+m*(36m+10). The complete wire additionally preserves the RHS serialization plus two pair brackets. The input explicitly contains m rows, so m<=input bit length is an elementary encoding-size lemma to prove. This gives polynomial OUTPUT SIZE, while same-function FP follows separately from the compositional construction above. Neither relies on numeric original labels being polynomial in m. Arbitrarily huge binary labels merely increase the input length; equality compares their bitstrings rather than expanding their values. Exact runtime exponent need not be guessed from output size.
