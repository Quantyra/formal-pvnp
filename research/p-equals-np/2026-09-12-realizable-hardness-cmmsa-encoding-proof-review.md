## Adversarial proof audit

**Faithful explicit data.** Data stores a list of rational weights, a dependent list of existing positive AND/OR formulas over precisely that coordinate count, and a rational budget. Valid requires strictly positive normalized weights, a nonempty formula list, the fixed leaf bound, and budget in (0,1]. There is no arbitrary semantic function or source-distribution oracle inside the instance record. Zero coordinates cannot satisfy normalization. Formula occurrences remain indexed list positions; duplicates are neither merged nor reweighted.

**Parsing and representation.** Tree.parse is structurally fuelled by nesting depth. Its prefix/suffix theorem, together with depth bounded by encoded length, justifies the decoder's input-length-plus-one fuel. decode checks empty trailing input and accepted semantic data. The parser checks zero denominators, formula tags, variable bounds, and validity. Examples witness denominator/index/empty-list/leaf/trailing rejection and an actual valid duplicate-occurrence instance. This is a total parser definition plus stated round-trip/rejection results, not a blanket runtime theorem inferred from examples.

Instance retains validated syntax. encode_injective concerns those syntax instances, not semantic equivalence classes: different leading zeros or unreduced fractions may denote the same Data. That is consistent with exact syntax round trips. Instance.valid ensures every successful instance has the intended semantic validity. decoded_data/yes/no preserve interpretation through an encode/decode round trip.

**Binary magnitudes and semantic surjectivity.** natTree uses actual binary digits with encoded size at most 4*Nat.size(n)+1. ratTree uses numerator magnitude and denominator digits, with a corresponding field-size bound. Its exact recovery theorem requires nonnegative rationals; valid data is positive and satisfies this condition. Negative rationals are not silently represented by their absolute value in that theorem. formulaTree preserves each positive formula constructor and repeated leaf. read_dataTree, ofData_data and decode_encodeData cover every valid explicit semantic record, closing the earlier limitation of only encoding already-validated syntax.

**Coordinate transport and ordering.** indexedData uses List.ofFn and an explicit finite-length cast. indexedData_count preserves every occurrence. Repeated sampled formulas still have separate trial positions and exception coordinates.
