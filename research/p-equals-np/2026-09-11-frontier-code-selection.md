## Exact input and output

Use n for original CNF variables and M=ceil(C n^(7/5)) for code length. B is n-by-M with independent uniform weight-three columns; nu contains independent random clause-sign parity bits. The query is Bq=0, nu dot q=1, 0<wt(q)<=k, with k=Theta(n^(1/5)). Equivalently use A=[B;nu] and target syndrome (0,...,0,1). Keep rank explicit rather than assuming a dense random matrix. The code rate is at least 1-(n+1)/M and tends to one; k/M=Theta(n^(-6/5)) tends to zero. This is neither constant-rate dense decoding nor a supplied random planted low-weight error.

One exactly verified vector is only one inconsistent tuple. A useful FKO result additionally requires enough distinct tuple weight with controlled original-clause loads. All construction, failed attempts, list memory, verification and packing costs count. Our prior [MITM comparison](2026-09-11-nonkilled-alternatives.md) gives lists sum_(j<=k/2) binom(M,j), still exp(Theta(k log(M/k))). Existing sharp spectral refutation also has n^O(k) cost in this regime; a meaningful leading-exponent improvement must compare explicit constants and output contracts, not just big-O classes.

## Why a tempting ISD exponent is not yet an advance

A naive dense-code calculation would count the chance that a small error support lies in a sampled redundancy block, then invert that chance. In our notation this suggests factors resembling (M/n)^k, which could look smaller than a full MITM list. But two missing hypotheses are material.

First, a block of n probabilistically independent sampled weight-three columns has expected number of all-zero rows n(1-3/n)^n, asymptotic to e^(-3)n. Thus dense full-rank heuristics are not even qualitatively justified for such blocks. This elementary expectation is not itself a probability lower bound on all ISD runtimes. Pivoting through the full matrix can avoid rejecting singular blocks, as ball-collision already explains, but changes the selected-basis distribution. One then needs the actual probability that a short solution has the required distribution relative to those pivots. No negligible-bias claim for this ensemble follows from the dense-code analysis.

Second, our solutions are determined by sparse dependencies and an odd sign query, not an independent uniform-weight planted error. Appending nu correctly expresses the syndrome, but does not convert the remaining matrix or solution set into a generic random-code distribution. Repeated solution recovery must also avoid concentrating all output on one tiny dependent region. Neither issue is repaired by quoting an asymptotic numeric exponent.

A concrete candidate would need a specified pivot/list-generation rule and a bound on its true collision yield, including false joins and memory, on this ensemble. No such favorable bound was derived in this selection. Generic ISD remains a legitimate algorithm family to analyze, not a justified new gain here.

## The restricted fixed-parameter possibility

A 2^O(k) poly(n,M) algorithm finding a short odd dependency in this sparse ensemble would remove the log n factor from n^O(k). A k^O(k) poly(n,M) bound would not remove that scale at k=Theta(n^(1/5)), although a checked leading-constant improvement could still matter. General Even Set hardness does not dismiss it. An unsigned column-weight-three finder alone is not automatically the signed query: appending nu gives columns of weight three or four. An alternative sign-blind family construction followed by sign filtering is valid only with sufficient family mass and load control. Conversely, bounded column weight alone does not furnish it: each selected clause has only three incidences, but the identities of the O(k) touched rows must still match with even multiplicities. Coloring/compressing those rows can create false parity cancellations between different original rows. Verification rejects such outputs, but does not bound how many false candidates must be processed or how many true solutions survive the filter.

A uniform guarantee for arbitrary column-weight-three inputs, a guarantee only for the original iid ensemble, and a guarantee surviving adaptive capacity/deletion residuals are different statements. None is imported from another. In particular, iid first-output success does not supply the conditional residual guarantee needed for repeated packing.

The narrow unproved obligation is therefore a charged algebraic sieve or structured list compression that preserves enough true sparse dependencies while controlling false matches, then yields a useful load-controlled family. A generic FPT wish or an unspecified minimum-weight oracle is not a candidate mechanism. Focused primary searches did not recover a theorem proving or ruling out this exact column-weight-three, iid, random-sign case. This is a search limitation, not a declaration that the restricted parameterized problem is newly open. No source-supported concrete rule survived selection, so no new derivation campaign is recommended by this note.

## One unselected proof question about an existing heuristic

A future experiment-free attempt could analyze the actual global heuristic: assign random priorities to all clause columns, greedily retain linearly independent columns, then construct each nonbasis column's fundamental circuit and check its support and sign exactly. This is standard Gaussian/matroid basis processing, not a proposed new algorithm. It is distinguishable from S3064's formula-independent variable restrictions and S3066's capped local incidence exposure: it uses the full matrix and allows a globally constructed basis, so those failure bounds do not directly cover it. It also overlaps conceptually with existing Gaussian dependency extraction and the independent-column construction already discussed in ball-collision; no new prior-art claim is made. The specific missing estimate is the probability that a fixed short minimal dependency becomes a fundamental circuit under these sparse greedy pivots, accounting for competing columns, followed by aggregate distinct-output and load bounds. Establishing a useful ensemble guarantee could be a model-specific application, but fixed-circuit survival alone would not establish packing. This is an unselected possible proof question, not a recommended or initiated campaign, and no claim is made that its exact analysis is absent from all prior literature.
