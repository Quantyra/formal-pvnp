## Representation and promise audit

The wire language is explicit finite binary syntax. Tree tags, lists, natural digit strings, rational numerator/denominator pairs, and the actual positive AND/OR Formula constructors are represented. Variable indices are checked against the explicit coordinate list. Validity requires strictly positive coordinate weights, sum exactly one, a nonempty ordered formula list, every formula's leaf count at most the external fixed L, and rational budget in (0,1]. Zero denominator, bad variable indices, malformed tags, trailing bits, empty lists and invalid data are rejected. Noncanonical rational representations are accepted without collapsing distinct wire instances; this is harmless for semantic correctness. No finite instance contains arbitrary probability or formula functions as fields.

`read_dataTree`, `ofData_data`, and `decode_encodeData` establish recovery of every valid explicit dependent Data record, so this is more than a round trip restricted to preexisting syntax. `Instance.valid` establishes validity in the other direction for accepted syntax. These do not say every bit string is valid or that semantic equivalence implies byte identity.

`indexedData` uses list positions, including duplicate formulas. Repair adds one distinct exception coordinate per position, even if sampled source formulas coincide. The exact leaf cost is +1, retained in the hypothesis on the source family; no deduction of a source leaf bound from an arbitrary fixed L is claimed.

`outputData_valid` discharges output validity from the actual upstream parameter structure and output_valid theorem. That structure contains weight and numerical constraints, not a final YES or NO conclusion. The coordinate equivalence covers all original and exception coordinates. `output_cost` and `output_satisfaction` preserve the actual complete cost sum and uniform occurrence average under that equivalence. Consequently output_yes_iff is realizability of every occurrence, using M>0, and output_no_iff quantifies over every assignment at the expanded budget with a strict threshold. Neither drops exception coordinates nor replaces the syntax with an arbitrary satisfaction function. The separate preservation theorems have genuine source-side YES and NO hypotheses.

Generic Codec Yes(epsilon) and No(sigma,gamma) are predicates for unrestricted rational parameters, not automatically a disjoint promise problem. For example epsilon=0, sigma=1, gamma=2 permits overlap for a valid fully satisfiable instance. The intended Pipeline instantiation avoids this: its actual Parameters and output_valid give gap=(sig/4)/2 >= 1 and 0 < 2*gam < 1, with positive output budget. A realizable witness at the original budget is therefore also within the expanded budget and has satisfaction one, contradicting strict NO. This disjointness follows mathematically from the inspected statements; these six files do not package a separate Lean PromiseProblem disjointness theorem. That packaging remains an integration obligation, not a bug in the current semantic equivalences.

For each fixed seed array, seeded_record identifies the entire decoded output data, and seeded_yes_iff/seeded_no_iff identify the exact prior SamplingFormulaPromises events for the actual sampleArray. No uniform-distribution, independence, or final success probability is hidden in these equivalences. The seed inputs and cumulative normalization are explicit. Positivity/distribution assumptions needed to obtain probabilistic sampling bounds must come from the actual sampler interfaces, rather than being inferred from cumulative normalization alone.

## Complexity limits and remaining work

1. Natural encodings use binary digits, with wire bound 4*size(n)+1; rational fields use 4*size(abs numerator)+4*size(denominator)+3. Parser fuel is the input bit length plus one and measures tree nesting. There is no encoding of a natural by a list of that many unary cells. These facts establish representation scale, not an FP theorem or a formal parser-time bound.
2. The full formula payload, occurrence count, coordinate count, rational arithmetic, reduced denominator sizes, and total encoded output length still need bounds relative to the encoded source input. Source numerical bounds P,Q in the upstream denominator theorem are not automatically polynomial in input bit length. They must be derived for the actual fixed-L reduction. Finite enumeration via List.ofFn is not by itself polynomial when its length may be exponentially large in the source encoding.
3. outputData, outputBits, and seededInstance remain explicitly noncomputable through semantic rounding definitions. Even computable Lean definitions would not imply FP. A concrete total tape executor must compute actual rounding, sampling and lists and be proved equal to this semantic output. Its malformed-source and failed-seed policy, finite source encoding, polynomial coins, and actual machine clock remain outstanding.
4. Upstream p : Nat -> Rat and F : Nat -> Formula are semantic theorem parameters. Only finite selected occurrences are encoded here. These modules do not supply a binary source encoding or efficient oracle for arbitrary p/F. The actual reduction must replace this interface by finite encoded data with proved evaluation cost.
5. Pointwise seeded promise equivalences are ready for explicit transport of probability bounds, but these files do not prove an encoded randomized reduction, source NP-hardness, the specialized PCP/decoder chain, final fixed-L asymptotics, or the learning statement. The full fixed-L theorem must discharge size and parameter choices; allowing its polynomial exponent to depend on fixed L is different from a uniform growing-L polynomial bound.
